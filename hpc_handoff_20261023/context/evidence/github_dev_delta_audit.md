## Ordinary dev changes

1. **Calibration changes both the null population and thresholds.** Main takes the mean from the opposite-orientation misalignment statistics, but its standard deviation is from `adapter_stats` (`stats.get_sd()`), not from that misalignment object; its stored threshold tuple is round(mean − sd), floor(mean), round(mean + sd). Main's default calibration cap is 50,000 reads. Dev partitions the edit-distance histogram at a valley below its main mode when a distinct lower-count-distance group exists, then uses the retained “chance-hit” group. Its lower threshold is the greatest edit distance whose cumulative chance-hit share is at most 0.05, floored at zero. The middle and upper thresholds use the chance-group mean and SD. The masking generator also receives these chance-group statistics. Both versions use the length-based fallback when calibration is insufficient; the fallback is max(1, ceil(0.30 × adapter length)). Dev starts with 50,000 reads and can add 50,000-read blocks, requiring at least 100 chance hits per element, with a nominal cap of 1,000,000 reads. It stops earlier if the projected required sample exceeds the cap, including when an element has no chance hits. A larger user-specified initial prep sample can raise this cap. Existing saved position maps remain reusable and can bypass recalibration.

## Optional HMM: a distinct method, not a default-main claim

Main does not contain `concat_hmm.hpp`. In dev, `--concat-hmm` is false by default. When enabled, a calibrated layout HMM routes confident single constructs to windowed static alignment and splits confident concatemers into child records. Calibration can be read from saved `hmm_*` position-map fields or obtained from the first 50,000 reads. The default abstention policy is **drop**; `--concat-hmm-abstain=legacy` requests the older route for eligible abstentions. Calibration guard failure, no detected construct, and certain barcode-less artifacts can still use the existing path. Unresolved boundaries retain the raw parent once in a separate file and do not make that raw copy an additional demultiplexed molecule. One-sided boundary results receive an HB layout-edge tag.

Model defaults include a construct cap of 256, terminal minimum length of 60, single-construct posterior threshold 0.99, and junction posterior threshold 0.90. Some limits are layout-derived. These parameters are internal defaults, not evidence of an executed paper analysis.

## Consequences for the working Methods

- The v2 generic alignment paragraph is broad enough to describe main, but is not a reproducible description of dev calibration or boundary handling. Keep main authority explicit. Do not silently insert dev-only behavior.
- The v2 barcode-correction paragraph's older seed-index caveat and its exhaustive-fallback description should not be confused with the new dev part-table optimization.
- The v2 record-count language must retain the historical emitted-record contract. It cannot be interpreted as an HMM-derived molecule-counting result.
- The runtime and biological analyses explicitly identify historical RAD revisions, including 4acbe00; the synthetic benchmark identifies 24d5ce4. Neither current snapshot alone establishes which later changes existed in those runs. Preserve their command logs and saved layouts as the run authority.
- The measured-error labels should remain operational: (1) a chemistry-catalog-valid input barcode outside the Cell Ranger set assigned into the selected set, and (2) a Cell Ranger barcode reassigned to another Cell Ranger barcode. These are measured assignment outcomes; they do not establish biological cell identity or biological certainty.
- Adaptive whitelist discovery itself is unchanged between these snapshots: `include/rad/whitelist_generator.hpp` has SHA-256 `c8f5b45c833acc2bfc599e38d7e443aa1f9cc178562ece0a3485855ce254624c` in both. This does not imply all surrounding input/loading behavior is unchanged.
- The existing `docs/cli-reference.md` and `docs/architecture.md` are also byte-identical between branches. They therefore cannot serve as a complete description of the dev delta; use the pinned implementation and the new boundary/loading document.
