## Read structure annotation

RAD accepts a comma-separated layout file that describes the order of elements in a read from 5′ to 3′. Static elements have known sequences and include primers, adapters, linkers, and poly-T tracts. Variable elements include cell barcodes, unique molecular identifiers (UMIs), and the captured cDNA sequence. Each variable element is assigned a class, an expected length where applicable, and a position relative to adjacent elements. The layout can specify more than one barcode element. RAD provides template layouts and accepts user-defined layouts. Reverse-complement elements are generated from the input layout unless the layout is restricted to one orientation.

Static elements provide anchors for variable-element extraction. For elements upstream of the cDNA, position rules are assigned from left to right. For elements downstream of the cDNA, rules are assigned from right to left. The cDNA interval is then defined from its adjacent elements. Secondary rules permit extraction when an optional anchor is absent, including a missing poly-T tract or terminal adapter. Layout preparation can estimate anchor positions and edit-distance limits from a sample of reads. Perfect alignments in one orientation provide the expected anchor positions. Alignments in the opposite orientation provide a misalignment distribution. The distribution is used to set anchor-specific limits. If fewer than 100 misalignment observations are available, or the estimated mean is invalid or below one edit, the fallback limit is the ceiling of 0.30 times the adapter length, with a minimum of one edit. The prepared layout and position map are saved for reuse.

## Static alignment, variable extraction, and concatemer processing

RAD first aligns static elements with Edlib in infix mode, with custom base equalities for masked positions. Edlib returns candidate locations at the best edit distance. Striped Smith–Waterman alignment is used when the primary alignment does not provide a suitable location. The accepted locations, alignment scores, and layout rules determine the intervals for barcodes, UMIs, and cDNA. Static sequences are masked before downstream extraction. The resulting structure is checked for consistent element order, required variables, sufficient cDNA length, and incompatible overlaps. Barcode and UMI sequences from reverse-oriented molecules are returned in the forward orientation; an option retains UMIs in their extracted orientation.

Concatemer processing uses static-anchor evidence to identify multiple molecules within one parent read. Forward and reverse molecules are assessed against the same layout rules. The later implementation also retains repeated static-anchor locations from the original alignment results and groups complete repeated-orientation molecules. A proposed split requires ordered anchors around the cDNA and all variable elements, sufficient intervening sequence, and support from the original primary alignments. Ambiguous or incompletely supported structures retain the original processing path. Each accepted child receives a bounded sequence and quality interval and is processed by the existing extraction, barcode-correction, and filtering steps. Parent-read counts and emitted-molecule counts are recorded separately. This procedure reuses the detected locations and does not constitute an exhaustive search for all damaged repeats.

## Barcode representation and correction

RAD maintains a sample-specific barcode set and, when supplied, the broader barcode catalog for the library chemistry. The sample-specific set can be obtained from long-read whitelist discovery or provided externally, for example from matched short-read data. Each barcode is encoded with two bits per nucleotide (A=00, C=01, T=10, and G=11), with 32 nucleotides per 64-bit storage unit. Unique barcode records contain counters for direct observations, corrected observations, total observations, orientation, and concatemer status. Lookup structures associate observed sequences with their candidate barcode records.

Before correction, RAD checks extracted sequences for low complexity, homopolymer tracts, and matches to static-element-derived k-mers. The homopolymer threshold is the larger of four bases and the integer part of 40% of the barcode length. Low complexity is defined as fewer than four distinct dinucleotides. An exact identity in the sample-specific set can override a collision with a static-element k-mer. Exact catalog identities are considered before fuzzy matching.

Unresolved sequences are compared with candidate barcodes using a bit-parallel edit-distance implementation. The search includes barcode-length windows in the surrounding sequence and mutation-derived candidates. For sample-specific sets with more than 10,000 unique barcodes, a three-part seed index provides an initial shortlist. Candidate entries are collected from matching fixed-position segments and checked at edit distance two. If this step does not produce an accepted result, an exhaustive comparison with the sample-specific set is used. The seed index is an acceleration step and does not replace the fallback search. Search paths for the sample-specific set use a distance limit of two; some broader-catalog paths use a limit of four.

Candidate resolution uses edit distance and direct-observation status. In the multiple-candidate lookup path, the first distance level with directly observed candidates is considered. A single candidate can proceed to the count-based acceptance check; multiple candidates at that distance are rejected. Exhaustive matching also requires a unique best-distance candidate. Equal-distance candidates are not resolved by selecting the most abundant barcode.

The count-based acceptance check limits repeated correction to poorly supported targets. A new candidate can receive an initial correction allowance. With fewer than two direct observations, correction is blocked after five total observations in defensive mode or ten in offensive mode. A blocked target can be restored after it accumulates two direct observations. Once a candidate has at least ten total observations and two direct observations, the prospective corrected fraction, (corrected count + 1)/(total count + 1), must not exceed 0.80. Defensive mode searches the broader catalog first in the fuzzy-matching stages; offensive mode searches the sample-specific set first. These checks use running counts and therefore do not impose an absolute requirement for a direct observation before every accepted correction. For joint barcodes, strict mode requires every component to pass.

## Whitelist discovery

Whitelist discovery aligns an adapter and extracts adjacent candidate barcodes. If a chemistry catalog is supplied, only catalog-matching identities are analyzed for cell calling. For each barcode i, the count cᵢ is transformed to xᵢ = ln(1 + 10⁶cᵢ/N), where N is the total number of extracted candidate barcodes before catalog filtering. The initial floor is x=2. A Gaussian kernel density estimate is calculated for barcodes above this floor on a 512-point grid. The bandwidth is 0.9 × min(SD, IQR/1.34) × n⁻¹⁄⁵, with a positive fallback when this estimate is degenerate. Peaks must reach 20% of the maximum density, and lower neighboring peaks within 0.5 log units are suppressed. When two or more peaks remain, the threshold is derived from the valley between the two tallest peaks and extended to the left boundary of the valley plateau.

A positive-count Poisson calculation provides a fallback when no stable valley is available. Its rate is the mean positive raw barcode count, and the candidate threshold is the smallest transformed count at or above the 95th percentile of the distribution conditional on a nonzero count. A single-mode guard retains the above-floor population when the sole peak is at least two bandwidths above the floor and the fallback threshold lies within two bandwidths to the right of that peak. Separate density estimates for provisional high- and low-count groups provide a 50% mixture boundary. This boundary is diagnostic when a stable saddle exists and can refine the threshold only in the absence of a saddle.

The selector also evaluates the distribution below the initial floor. It uses the adjusted upper-tail hazard H(x) = (1−exp(−x))f(x)/S(x), where f(x) is the density of unique-barcode scores and S(x) is the upper-tail survival function. A lower-floor candidate must occur at bandwidths 0.8h, h, and 1.25h with a spread of no more than 0.5h. It must have at least 5% local prominence, at least 50 supported barcodes on each required side, and add at least the larger of 50 barcodes or 1% of the original above-floor population. The candidate is mapped to an observed count level. It can replace the initial floor only when the expanded distribution has the ordered features hazard, left peak, saddle, and right peak, and every barcode rescued below the saddle satisfies the 95th-percentile positive-count Poisson criterion.

A further hazard check evaluates whether a prominent boundary at or below the preliminary gate should set the final threshold. A candidate below the floor must coincide with the stable three-bandwidth feature or lie within half a bandwidth of the floor. If it expands a set supported by a stable saddle, it must also satisfy (Kₕ−K₀)/(M−K₀) ≤ (M−n₊)/M, where M is the catalog size, n₊ is the number of observed catalog barcodes, K₀ is the preliminary number selected, and Kₕ is the proposed number selected. An accepted hazard boundary determines the final cutoff.

When no hazard boundary controls the result, safeguards prevent a small or narrow lower-count group from dividing a single population. All above-floor barcodes are retained if the lower group is at most 10% of the above-floor population, both sufficiently populated groups have ranges of at most one log unit, or the full range is at most two log units. If the lower group accounts for more than 10% but no more than 20%, up to 10% of the above-floor population is rescued from that group in descending count order. The default output contains the final high-specificity calls. A separate option returns all above-floor candidates. Barcode counts, thresholds, selection rules, and final calls are recorded in the output tables and logs.

## Processing and output

Reads are processed in bounded chunks with OpenMP parallelism and buffered output. Compressed input and output use pigz when available, with a zlib fallback. Demultiplexed reads contain cell-barcode and UMI tags for downstream analysis. A separate reformatting command can rewrite headers, split output by cell barcode, or map joint spatial barcodes to coordinates. Software commits, layouts, whitelist inputs, thread counts, and nondefault settings are recorded separately for each benchmark because the analyses were performed with more than one RAD revision.
